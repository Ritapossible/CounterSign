# CounterSign - working notes for agents

A board of "audited by" claims on GenLayer: a claim stands only while the
auditor's own page confirms it. Two contracts: a **Board** (money, records)
and a **Reader** (fetches the page, asks the jury). Read
`docs/ARCHITECTURE.md` first.

Status: design. Follow PLAN.md phase by phase; do not skip the probe.

## Hard laws

These are the product. A change that breaks one is wrong even if tests pass.

1. **No path pays the auditor.** Stakes go only to the project or to the
   keeper whose re-check took a claim down. `test_no_path_pays_the_auditor`
   and its mutant must stay.
2. **No model on the happy path.** An exact, complete, visible sentence with
   ordinary surroundings is decided by code. The jury is asked only when the
   sentence is present but its surroundings changed (or hold a withdrawal
   word at posting).
3. **Scope is exact strings.** `subject` and every `scope` string must be
   substrings of the normalised sentence. Never add fuzzy matching or ask a
   model whether two scopes are "the same".
4. **Only `confirms` keeps a claim.** `denies`, `points_elsewhere`,
   `cannot_tell` and anything unparseable do not.
5. **One silent read never takes a claim down;** two, `MISS_GAP` apart, do.
6. **Hidden text is not text.** Use the visible-text rules carried from
   RedLine; never weaken them.
7. **The project never supplies the page URL.** It is fixed by the auditor at
   registration and cannot be edited.
8. **URLs are refused, never decoded:** no `%`, `..`, `\`, `@`, `?`, `#`,
   whitespace (Remit Milestone 1).
9. **The Board never reads the Reader.** Reports arrive as messages from the
   Reader's address only; reads are numbered.
10. **A payable method never raises after value has arrived.** Refuse by
    recording `refused` and refunding.
11. **Never claim a JavaScript page, an image, a PDF or a canvas is
    readable.**
12. **Every number in the README comes from a record in `deploy/`.**

## Hard rules from earlier projects (learned on chain)

- The runner header is the first line of a contract, followed immediately
  by code; a comment between them fails the deploy with an empty stderr.
- The web fetch is written inline in both the leader and the validator
  closure, never in a helper.
- Every value a closure captures is a plain Python value.
- Validators compare outcomes, never page bytes or whole-page text.
- `contracts/build/` is generated by `python3 deploy/build_contract.py`;
  never edit it by hand; commit it.
- Bradbury caps a deploy at about 19 KB minified; keep
  `test_it_fits_bradburys_gas_cap`.
- Never print or commit private keys.
